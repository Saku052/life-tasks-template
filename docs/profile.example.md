# プロフィール（テンプレート）

このファイルをコピーして `docs/profile.md` を作り、自分の情報で埋める。

```bash
cp docs/profile.example.md docs/profile.md
```

`docs/profile.md` は `.gitignore` 済み。**氏名・所属・生活圏が入るため、コミットしない前提**で作ってある。

`task-add` / `task-board` / `daily-brief` が、**タイトル・ラベル・優先度・期限を自分で決めるため**に読むファイル。
ここが埋まっているほど、「〇〇やらないと」の一言だけで正しい Issue が立つ。
逆にここが空だと、Claude は毎回聞き返してくることになる。

> **書かないもの**: 口座番号、パスワード、マイナンバー、クレジットカード番号、
> 詳細な診断名や病歴、他人の実名や連絡先。
> **勤務先や通学先は「店舗名・キャンパス名」まで書くと個人が特定できる**ので、
> 「A社のバイト」「大学の研究室」程度の粒度で十分機能する。

## 固有名詞 → ラベル 対応表

**ここが一番効く。** 発言に含まれた語からラベルを機械的に決めるための辞書。
下の一般語はそのまま使い、**自分の固有名詞（サークル名・勤務先・プロダクト名・イベント名）を
行に足していく**のが運用の肝。固有名詞が増えるほど、聞き返されずに正しいラベルが付く。

| 発言に出たら | ラベル |
|---|---|
| 授業, 講義, 課題, レポート, 提出, 試験, 期末, テスト, 単位, 履修, 履修登録, ゼミ, 研究室, 配属, 卒論, 発表 | `Study` |
| 就活, ES, エントリー, 面接, 面談, インターン, 説明会, 選考, OB訪問, 適性検査, ガクチカ | `Career` |
| バイト, シフト, 勤務, 給料, 出勤 ＋〈自分の勤務先〉 | `Work` |
| サークル, 部活, 練習, 新歓, 合宿, 学祭, 幹事, 会費 ＋〈自分の団体名・イベント名〉 | `Circle` |
| 実装, 直す, バグ, リファクタ, デプロイ, リリース, PR, レビュー, issue ＋〈自分のプロダクト名〉 | `Dev` |
| 読む, 勉強, 写経, 検証, 触ってみる, 資格, 公式ドキュメント ＋〈学習中の技術名〉 | `Tech` |
| 投稿, 発信, ネタ, あとで読む ＋〈使っているSNS〉 | `Idea` |
| ジム, 筋トレ, 走る, 病院, 通院, 健康診断, 予約, 睡眠 | `Health` |
| 更新, 役所, 免許, 保険, 実家, 帰省, 手続き | `Life` |
| 学費, 奨学金, 支払い, 振込, 家計 | `Money` |
| 毎週, 毎月, 定期的に | `Routine`（他のラベルと併用） |

判断が割れやすいものは、決めた結果をここに書き足しておく。例：

- **適性検査の勉強** → 就活のための勉強なので `Career`。ただし「参考書を読む」のように
  学習行為が主語なら `Tech` も付けてよい
- **イベントの立替金** → `Circle` と `Money` の両方
- **このリポジトリ自体の改善** → `Dev`

複数当てはまったら2つまで付ける。
どれにも当たらない語が出てきて判断が固まったら、**この表への追記を提案させる**（勝手に書き換えさせない）。

## タイトルの付け方

- **動詞で終える。体言止めにしない。** 「レポート」ではなく「◯◯のレポートを提出する」
- **固有名詞を必ず入れる。** 「病院に行く」ではなく「歯科のクリーニングを予約する」
- **20〜30文字。** ボードのカードで折り返さない長さに収める
- **接頭辞は付けない。** 領域はラベルが持つので `[Study]` などは不要
- 繰り返すものは末尾に回次を入れる: 「実験レポートを出す（第5回）」

## 優先度の既定

明示がないときはこの規則で決める。**「動かせない締切かどうか」で判断する。**

| 条件 | Priority |
|---|---|
| 締切が3日以内 / 落とすと単位・選考・信用を失う（課題提出・ES・面接・シフト提出） | `P0` |
| 締切が今月内 / 誰かを待たせている（他人との共同作業、返事待ちにさせている） | `P1` |
| 締切なし / 自分の都合だけで動かせる（個人開発、学習、発信） | `P2` |

## 期限の推定

日付が明示されなくても、次の語からは `Due` を埋める。

| 発言 | Due |
|---|---|
| 今日中 / 今日 | 当日 |
| 明日 | 翌日 |
| 今週中 | 直近の金曜 |
| 来週 | 翌週の金曜 |
| 今月中 | 月末 |
| 〜までに | その日の前日 |
| 次の授業まで | 科目名から曜日を確認してから決める |
| シフト提出 | 〈自分の締切日〉 |

推定した場合は Issue 本文の「## 概要」に**根拠を1行書く**
（例:「『今週中』と言われたため金曜を期限に設定」）。

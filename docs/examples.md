# 運用例

実際に運用しているボードから、**個人が特定できる情報を伏せて**典型パターンを抜き出したもの。
企業名・団体名・店舗名・人名はすべて「A社」「音楽サークル」のような一般名に置き換えてある。

---

## 1. 一言からIssueが立つまで

これがこのリポジトリの中心的な体験。ユーザーは締切と用件だけを言う。

**入力**

```
タスク追加：8/30までにA社のESを提出
```

**Claude がやること**

1. `docs/profile.md` を読む
2. 「ES」→ 対応表から `Career` ラベル
3. 「〜までに」→ 期限の推定表から **Due = 8/29**（締切の前日）
4. 「ESは動かせない締切」→ 優先度の既定から **P0**
5. タイトル規則（動詞で終える・固有名詞を入れる）に従って命名
6. `./scripts/task.sh add` を1回呼ぶ

**出てくる Issue**

```markdown
## 概要

A社のエントリーシート締切が8/30。動かせない締切なので、推敲と提出トラブルの
余裕を見て前日8/29を期限に設定した。

## 完了に必要な手順

- [ ] マイページで設問と文字数・提出方法を確認
- [ ] ガクチカの初稿を書く
- [ ] 志望動機の初稿を書く
- [ ] 1日寝かせてから推敲し、文字数を調整
- [ ] 第三者（キャリアセンターか先輩）に読んでもらう
- [ ] マイページから提出

## 完了条件

A社のマイページでESの提出完了が表示されている

## 期限

2026-08-29
```

`Career` / P0 / Due 2026-08-29 / ステータス `To do`。**ここまで一度も聞き返していない。**

聞き返さないことが成立するのは、判断材料が `docs/profile.md` に全部書いてあるから。
プロフィールが空だと、この体験は成立しない。

---

## 2. 期限が後から分かるケース

日程が未定のまま起票し、決まってから入れる。

```
> タスク追加：発表会に向けて練習する。もう1人と担当パートを分ける
```

このとき期限は**空のまま**にする。プロフィールの期限推定表に当てはまる語がないので、
無理に埋めない。代わりに概要へ「本番日が未確定のため期限は未設定」と根拠を残す。

日付が判明したら1コマンドで入る。

```bash
./scripts/task.sh due 11 2026-09-17
```

Projects の `Due` フィールドと Issue 本文の「## 期限」が同時に更新される。

**担当分けを別Issueに切り出さない**のがポイント。担当が決まらないと練習範囲が決まらない
＝前提条件なので、同じIssueのチェックリスト先頭2項目に置く。
Issue を細かく割りすぎると、ボードが「やることリスト」ではなく「思いつきリスト」になる。

---

## 3. 他人待ちのタスク（Pending の使い方）

```markdown
タイトル: 合同イベントの顔合わせ日程を決める
ラベル: Circle / 優先度: P1 / 期限: なし

## 概要
複数団体の日程調整を回す必要がある。相手を待たせる調整なので早めに候補日を投げる。

## 完了に必要な手順
- [ ] 各団体の担当者と連絡手段を洗い出す
- [ ] 候補日を3つ出す（対面/オンラインの別も決める）
- [ ] 日程調整フォームを作って共有し、回答期限を伝える
- [ ] 回答を集計して開催日時と場所を確定する
- [ ] 確定日時を全員に通知しカレンダーに登録する

## 完了条件
顔合わせの日時と場所が確定し、関係者全員に共有できている
```

候補日を投げて返事待ちになったら Pending へ落とす。**理由を必ず添える。**

```bash
./scripts/task.sh move 10 pending --reason "3団体に候補日を送付、回答期限は9/5"
```

理由は Issue のコメントに残る。1ヶ月後に見たとき「何を待っていたか」が分かる状態を保つ。

**Pending にしていいのは「自分以外の要因で止まっているとき」だけ。**
気が乗らなくて止まったものは To do に戻す。ここを緩めると Pending がゴミ箱になる。

---

## 4. 定期タスク

シフト提出や家賃の支払いのように、周期が決まっているもの。

```markdown
タイトル: 次の半月分のシフトを提出する
ラベル: Work / Routine / 優先度: P0 / 期限: 毎月6日・22日
```

`Routine` は他のラベルと**併用する**。領域（`Work`）は残したまま「繰り返しである」ことを足す。
プロフィールの期限推定表に「シフト提出 → 毎月6日・22日」と書いておけば、
「シフト出さないと」の一言で正しい期限が入る。

---

## 5. 増えすぎたIssueを畳む

同じ話題のIssueが分裂したら統合する。

```bash
./scripts/task.sh merge 12 15 18
```

`#12` に `#15` `#18` のチェックリストが移り、残りは close される。
close を伴うので、Claude は実行前に対象を1行で提示して確認を取る。

放置されているものは検知できる。

```bash
./scripts/task.sh stale 7   # 7日間動いていないものを列挙
```

## ボードの見え方

```
To do (6)              Pending (2)           In progress (2)        Done
─────────────────      ─────────────────     ─────────────────      ─────
A社のESを提出する       顔合わせ日程を決める   発表会に向けて練習     ...
 Career P0 8/29         Circle P1             Circle P1 9/17
                        （3団体の返事待ち）
定期演奏会の練習        イベント会場を予約     資料を各所から回収
 Circle P2              Circle P1             Circle P1
                        （会場の空き待ち）
```

`In progress` は5件、`Pending` は10件が上限。
**上限は「これ以上増えたら現実を見ろ」という警告**であって、システムが弾くわけではない。

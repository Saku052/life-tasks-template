# デイリーブリーフ

タスクの進捗把握（Projects）と情報収集（トレンド収集スキル）を1本の流れにまとめる。

## 実行手順

### 0. プロフィールを読む

`docs/profile.md` を読む。学業・就活・バイト・サークルの定期イベントは、
今日やることを絞るときや期限を推定するときの判断材料になる。

**空き時間の推定はしない。** どれだけ着手できるかはユーザーが決める。
5件に絞って提示するところまでが役割。

### 1. ボードの現状を取る

```bash
./scripts/task.sh board
./scripts/task.sh stale 7
```

### 2. 今日やることを絞る

以下の順で拾い、**最大5件**に絞る。多く並べない。

1. 期限が今日〜3日以内のもの
2. `P0` のもの
3. すでに `In progress` のもの
4. Pending のうち、待ち対象が解消していそうなもの

絞った結果を提示し、着手するものが決まったら `./scripts/task.sh start <番号>` を実行する。

### 3. トレンドを収集する

`neta-trend-daily` スキルの手順を実行し、`ideas/daily/YYYYMMDD-trend.md` を作る。

ユーザーから URL が渡された日は、代わりに（または追加で）`url-digest` スキルを使う。

### 4. ネタをタスクに変換する

収集結果のうち、**読んで終わりにせず何かする**ものだけ Issue にする。目安は1日0〜3件。

```bash
./scripts/task.sh add \
  --title "OWASP Top 10 2025 の変更点を読む" \
  --summary "サプライチェーン攻撃の項が追加された。業務のレビュー観点を更新する必要がある。出典: <URL>" \
  --label Idea --label Tech --priority P2 \
  --check "変更点のdiffを読む" \
  --check "レビュー観点リストに反映" \
  --dod "自分のレビューチェックリストが2025版に対応した"
```

**変換しない基準**: 面白いだけ / 自分の領域外 / 3ヶ月後に価値が残らない。
これらは `ideas/daily/` のファイルに残るので、Issue にはしない。

### 5. まとめて報告する

この順で、簡潔に。

1. **今日やる（最大5件）** — 番号・タイトル・理由（期限/優先度）
2. **詰まっているもの** — Pending と待ち対象
3. **今日のトレンドから3行** — 一番効きそうなものだけ
4. **起票したもの** — あれば

ボードの生出力やトレンドの全件リストは貼らない。ファイルへのリンクで済ませる。

## 注意

- 勝手にステータスを動かさない。着手宣言があったものだけ `start` する。
- In progress が5件を超えている日は、新規着手を勧める前にそれを指摘する。
- トレンド収集は `curl` と `jq` を使う。失敗しても止まらず、ボードの報告は必ず行う。

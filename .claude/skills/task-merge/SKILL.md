# タスクの統合・整理

同じことを別の言い方で2回起票してしまう、細かく割りすぎて管理コストが上回る。
どちらもボードが読めなくなる原因なので、見つけたらその場で統合する。

## 実行手順

### 1. 候補を洗い出す

```bash
./scripts/task.sh list --json
```

重複の判定は**タイトルの文字列一致ではなく、完了条件が同じかどうか**で行う。

- 「保険を見直す」と「生命保険の乗り換え検討」→ 同じ。統合する
- 「確定申告」と「ふるさと納税のワンストップ申請」→ 別。関連 Issue として相互リンクするだけ

判断に迷うものは統合せず、ユーザーに1行で確認する。

### 2. 統合先を決める

以下の優先順で `keep` を選ぶ。

1. すでに `In progress` のもの
2. チェックリストの消化が進んでいるもの
3. Issue 番号が若いもの（履歴・コメントが多い側）

### 3. 統合する

```bash
./scripts/task.sh merge 12 15 18
```

これで起こること:

- `#15` `#18` のチェックリスト項目が `#12` の本文末尾に追記される
- `#15` `#18` に「重複のため #12 に統合しました」とコメントし、`not planned` で close
- 統合された側の Project ステータスを `Done` に落とす
- `#12` はステータスを保ったまま残る

### 4. 統合後を整える

本文が継ぎ接ぎになるので、必要なら整理する。

- 重複したチェック項目を1つに寄せる（`gh issue edit <keep> --body-file`）
- 概要が古ければ書き直す
- 消化済み項目は `- [x]` のまま残す（履歴として意味がある）

```bash
./scripts/task.sh show 12   # 統合結果を確認
```

### 5. Project 未登録の Issue を取り込む

Web UI や他経路で作った Issue はボードに載っていないことがある。

```bash
./scripts/task.sh sync      # open な Issue を全部 Project に追加し、To do に置く
```

## 逆方向：大きすぎる Issue を割る

チェックリストが15項目を超える、または完了まで1ヶ月以上かかるものは分割する。

1. 親 Issue の概要はそのまま残す
2. 独立して完了できる塊を `task-add` の手順で新規起票する
3. 親の本文に `- [ ] #34` のように子 Issue を参照で並べる（GitHub 側で進捗が自動集計される）

## 注意

- `merge` は close を伴う。実行前に統合対象と統合先をユーザーに1行で提示して確認を取る。
- 履歴を消さない。統合された Issue は削除せず close で残す。
- `not planned` で close されたものはボードの Done 列に出る。棚卸し時に紛れて見えるのは想定通り。
